# Порт куба на ESP32-S3

Дата карты: октябрь 2026. Цены — диапазоны AliExpress / Ozon / Wildberries / Чип и Дип, не оферта.

Ветка собрана от `src/2.8.15`. Кристалл другой. Поведение сеанса то же.

## Чего эта карта не делает

DevKit — это логика. Он говорит с уже готовым модулем заряда по CAN 250 кбит/с (GB/T 27930, семьи 2011 / 2015 / 2023-B, выбор на плате делает CAN, не меню).

Не подключать к плате:

- шины батареи и выход DC станции
- катушку сетевого контактора напрямую с GPIO
- 5 В на любой GPIO. ESP32 это убивает. Поэтому не TJA1050: у него RX пятивольтовый

Реле в прошивке — два логических выхода, активный высокий уровень, как GPIO6 и GPIO7 на кубе. HIGH на A — подготовка. HIGH на B — нагрузка, только когда выход станции держится. В простое оба LOW.

Дешевле и достаточно для SPI: DevKit **N8R2**, $5–9 / 600–1 100 ₽. До экрана 800×480 его не хватит.

Тише по проводам, но экран другой шины: **LilyGO T-Display-S3**, $15–25 / 1 800–3 500 ₽. В `display.c` 3.0.0 он не включён.

## Ноги DevKit, которые заняты до нашего кода

| Ноги | Почему свободными не считаются |
| --- | --- |
| 0, 3, 45, 46 | strapping. 0 ещё и кнопка BOOT |
| 19, 20 | USB, этим портом плата шьётся |
| 22–25 | у кристалла S3 их нет |
| 26–32 | flash внутри модуля |
| 33–37 | octal PSRAM у N16R8. Даже если пины торчат, трогать их нельзя |
| 43, 44 | UART0, лог клона на CH340 |
| 38, 48 | светодиод на DevKit, ревизии расходятся |

S3 — Xtensa LX7, два ядра, до 240 МГц. Старый куб был ESP32-C3, RISC-V, одно ядро, без LCD_CAM. Поэтому параллельный и RGB экран возможны только здесь, и только отдельным драйвером.

## Провода DevKitC-1, профиль по умолчанию

Экран SPI. Если на шелке модуля `3V3` — питать от 3V3. Пин `5V` только у плат, где стабилизатор уже стоит на модуле.

| Сигнал | DevKit | Модуль |
| --- | --- | --- |
| SCK | GPIO12 | SCL / SCK |
| MOSI | GPIO11 | SDA / MOSI |
| CS | GPIO10 | CS |
| D/C | GPIO13 | DC / RS |
| RST | GPIO14 | RST |
| Подсветка, ШИМ | GPIO21 | BL / BLK |
| GND | GND | GND |

Тач CST816S, адрес 0x15, как в `touch_cst816s.c`:

| Сигнал | DevKit |
| --- | --- |
| SDA | GPIO1 |
| SCL | GPIO2 |
| INT | GPIO4, можно не паять |
| RST | GPIO5 |
| питание | 3V3 |

CAN, SN65HVD230 или развязанный ISO1050 ($3–8 / 400–900 ₽), сторона микроконтроллера 3.3 В:

| Сигнал | DevKit |
| --- | --- |
| TX | GPIO17 → CTX |
| RX | GPIO18 → CRX |
| линия | CANH / CANL витой парой |

Резистор 120 Ом включать джампером только если этот узел на конце шины. В середине линии джампер снять.

Реле, питание модуля от пина 5V DevKit, земля общая:

| Сигнал | DevKit | Смысл в прошивке |
| --- | --- | --- |
| IN1 | GPIO6 | подготовка, HIGH |
| IN2 | GPIO7 | нагрузка, HIGH |

Катушка 12 В сидит на модуле реле или на низкостороннем ключе с диодом. Не на ножке чипа.

## LilyGO T-Display-S3, если вместо DevKit

Экран заводской, 8-бит i80, ST7789V, 170×320. Пины с вики LilyGO, не переназначать.

| Функция | GPIO |
| --- | --- |
| Питание периферии, держать HIGH | 15 |
| Подсветка | 38 |
| RST | 5 |
| CS | 6 |
| DC | 7 |
| WR | 8 |
| RD | 9 |
| D0 D1 D2 D3 | 39 40 41 42 |
| D4 D5 D6 D7 | 45 46 47 48 |

Свободное под нашу обвязку на этой плате: CAN TX GPIO1, RX GPIO2, реле GPIO10 и GPIO11. Разъём I2C уже занимает GPIO18 (SDA) и GPIO17 (SCL).

`display.c` этой ветки пишет в SPI (`SPI2_HOST`). T-Display так не заведётся. Открытый пример: репозиторий `Xinyuan-LilyGO/T-Display-S3` и `LilyGo-Display-IDF`.

## Сборка и прошивка пустой платы

ESP-IDF 5.0.9, уже установленный для куба. Из корня ветки `hw/esp32-s3`:

```
idf.py set-target esp32s3
idf.py build
python -m esptool --chip esp32s3 -p COM5 -b 460800 write_flash ^
  0x0 build\bootloader\bootloader.bin ^
  0x8000 build\partition_table\partition-table.bin ^
  0x10000 build\FGMDCharge_FD_ROUND_V2.bin
```

Смещение загрузчика у S3 такое же, как у C3: `0x0`, не `0x1000`.

Официальный DevKit с двумя USB: кабель в порт **USB** (ноги 19/20, консоль USB-Serial-JTAG). Клон с одним CH340: в `sdkconfig.defaults` заменить консоль на `CONFIG_ESP_CONSOLE_UART_DEFAULT` и убрать строку USB-Serial-JTAG, иначе монитор молчит.

`GO.bat` куба не запускать. Он пишет `esp32c3` и целится в ota_1, чтобы не затереть завод. На новом модуле завода нет, приложение живёт в ota_0.

В мониторе ждать `READY 3.0.0`. Точка `Cube`, пароль `12345678`, канал 6, страница `http://192.168.4.1/`.

## Порядок стенда

1. USB, лог, ни одного периферийного провода.
2. Только подсветка. GPIO21 должен зажечь BL.
3. Остальной SPI. Картинка. Если белая — invert.
4. Тач. Пропуск не ломает сеанс: уставки и так с сайта.
5. Трансивер CAN без автомобиля. Вторая плата или адаптер, петля на 250 кбит.
6. Модуль реле от 5 В. В простое тихо. Щелчок только из сеанса.
7. CANH/CANL на сертифицированный модуль GB/T. Не раньше.

PSRAM в 3.0.0 выключен. Включать octal на N16R8 только после первой картинки: неверный режим PSRAM даёт циклический сброс, и кажется, что виноват экран.

## Что сознательно осталось как в 2.8.15

- автомат состояний 0…7 и два реле
- веб только точкой доступа, OTA, лог сессии во флеш
- BLE выключен макросом, исходник Bluedroid на месте
- LVGL 8.3.11, буфер 64 КиБ во внутренней памяти
- таблица разделов и адрес лога `0x330000`

Гладкость интерфейса, на которую ругался куб, упиралась в одно ядро и внутреннюю память. S3 это снимает, но полный кадр в PSRAM — отдельный шаг после того, как SPI-картинка уже стабильна.
