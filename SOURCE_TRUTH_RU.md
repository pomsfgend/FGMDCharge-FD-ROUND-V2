# FGMDCharge / FD_ROUND V2 — SOURCE TRUTH

Этот проект является реконструкцией прошивки на основании полного 4 MiB dump `original/dump1.bin`, дизассемблирования извлечённого OTA-образа и проверяемой документации GB/T 27930.

## Что подтверждено дампом

- MCU: ESP32-C3; прошивка собрана на ESP-IDF v5.0.9.
- Flash: 4 MiB; OTA0/OTA1 по 0x190000.
- ILI9341: SPI MOSI=5, SCLK=19, CS=4, DC=18, 20 MHz; логическое разрешение 240x280.
- CAN/TWAI: TX=10, RX=9, 250 kbit/s, normal mode, accept-all filter.
- BLE: `FGMDCharge`, service 0xFFE0; FFE1 read/write/notify/indicate, FFE2/FFE3 write.
- NVS namespace `storage`; ключ BLE имени `BLEname`; соседние данные `Alldata` сохранены в оригинальном дампе.
- FreeRTOS задачи оригинала и их приоритеты/стек изучены и учтены в новой реализации.

## Что реализовано в реконструкции

- Приём и журналирование CAN с 29-bit GB/T ID.
- Декодирование подтверждённых CML/CCS/CRO/CST/CSD/CEM/BCL полей.
- Восстановление стадий зарядки на основе реально принятых сообщений.
- Generic GB/T/J1939 transport-protocol reassembly до 0x6F0 байт.
- BLE GATT service с исходной UUID-топологией.
- Локальная Wi-Fi AP и автономный Web UI.
- Защищённые ключом операции raw CAN, reboot и OTA.
- OTA пишет только неактивный app slot через ESP-IDF OTA API и не стирает соседний slot.
- LCD + LVGL + touch input.

## Что намеренно не выдумывается

- Точные ADC GPIO/channel и коэффициенты исходника не считаются доказанными. Поэтому `adc_pwm.c` работает в safe mode и не управляет неизвестными выводами.
- Точный BLE OTA packet framing старой прошивки не восстановлен до уровня, достаточного для безопасного воспроизведения. Произвольная BLE запись не запускает OTA.
- Полная автоматическая TX state machine силовой зарядки не включается при старте. CAN TX компилируется, но по умолчанию выключен и может быть включён вручную для стендового теста.
- Неидентифицированный хвост OTA0 сохраняется как оригинальный бинарный артефакт и не встраивается в новую прошивку.

## Главный принцип

Все значения, которые непосредственно управляют железом, либо подтверждены dump/документацией, либо отключены до стендовой верификации. Это отличается от «полной» прошивки неизвестным кодом: здесь цель — рабочая реконструкция без ложных предположений.
